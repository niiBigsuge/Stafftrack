# Project Requirements Specification: StaffTrack

> Generated by Olives Dev-OS (https://github.com/olitech1010/dev-os)
> System: Corporate Staff Attendance and Punctuality Management System

## 1. Executive Summary
StaffTrack is a web-based corporate attendance and punctuality management platform designed for modern organizations. Beyond simple presence tracking, StaffTrack enforces reporting times, calculates punctuality metrics, automates absence reconciliation, and delivers departmental benchmarks for management and Human Resources (HR).

The platform enables staff to record arrival and departure times through a personal web dashboard, submit punctuality explanations or missing attendance correction requests, and monitor their own attendance history. Department managers and HR administrators receive live daily operational rosters, automated late/absence flags, and comparative departmental scorecards to foster transparency and operational discipline.

## 2. Core Workflows (The Happy Path)

### Workflow 1: Staff Daily Clock-In and Punctuality Determination
1. Staff member signs in to the portal via desktop or mobile browser.
2. The dashboard displays the official work schedule (start time: 08:30 AM, grace window: 15 minutes, end time: 17:00 PM).
3. The staff member clicks "Clock In".
4. The system validates that no existing punch exists for the user on the current calendar date.
5. If the server timestamp is on or before 08:45:00 AM, the record is stored as `PRESENT_ON_TIME` with `minutesLate = 0`.
6. If the server timestamp is after 08:45:00 AM, the record is stored as `PRESENT_LATE` with calculated `minutesLate = (timestamp - 08:30:00)`. The UI displays a prompt allowing the staff member to submit an optional lateness reason immediately or later.

### Workflow 2: Staff Clock-Out
1. At the conclusion of the workday, the staff member clicks "Clock Out".
2. The system confirms an existing clock-in for the day, records `clockOutTime`, and calculates `totalWorkMinutes`.
3. The status indicator switches to "Completed for the Day".

### Workflow 3: Lateness Excuse & Attendance Correction Request
1. A staff member selects a late attendance record or identifies a missing punch date and clicks "Submit Explanation / Correction".
2. The user submits a structured request specifying the reason and (if applicable) corrected times.
3. The assigned department manager receives the request in their approval queue.
4. The manager reviews the justification and approves or rejects the request with an audit remark.
5. If approved, the system updates `isExcused = true` or updates the missing punch timestamps, triggering an audit log entry.

### Workflow 4: Daily Real-Time Attendance Oversight
1. HR Administrators and Executives access the live attendance dashboard.
2. The summary cards display total scheduled staff, on-time arrivals, late arrivals, absences, and staff on approved leave.
3. The roster table permits filtering by department, status, and search by employee code or name.

### Workflow 5: Departmental Punctuality Benchmarks & Reporting
1. Management reviews the departmental leaderboard, ranking units by punctuality percentage:
   `Punctuality Score = (On-Time Arrivals / Expected Workdays) * 100`.
2. HR exports granular attendance data and payroll summaries via CSV or formatted Excel for any selected date range.

## 3. Architecture & Tech Stack
- **Environment & Database:** ServBay running local MySQL 8.x.
- **ORM & Data Layer:** Prisma ORM with MySQL provider, connection pooling, and automated migrations.
- **Fullstack Framework:** Next.js 15 (App Router, React 19).
- **Mutations & Business Logic:** Next.js Server Actions with Zod validation.
- **Authentication & RBAC:** Auth.js (NextAuth v5) session-based authentication with role-based route guards (`STAFF`, `MANAGER`, `HR_ADMIN`, `EXECUTIVE`).
- **UI & Design System:** Tailwind CSS, shadcn/ui components, Lucide icons, accessible WCAG-compliant color contrast.
- **Scheduled Tasks:** Node-cron / Next.js scheduled route for automated end-of-day absence reconciliation at 23:59:00.

## 4. Edge Cases & Error Handling

| Scenario | Expected System Behavior |
|----------|--------------------------|
| Staff attempts to clock in twice on the same day | Unique composite constraint `[userId, recordDate]` rejects the mutation; UI indicates active clock-in with timestamp. |
| Staff clocks in after the grace cutoff | Record marked as `PRESENT_LATE`; exact late minutes calculated and visible to employee, manager, and HR. |
| Staff forgets to clock out at the end of the day | Record remains open with `clockOutTime = null`; flagged in the manager's anomaly review queue next morning. |
| Staff was sick or on approved leave | HR marks approved leave in advance; daily reconciliation records `ON_LEAVE` instead of `ABSENT`. |
| Unexcused employee fails to punch in all day | End-of-day cron job detects absence at 23:59:00 and generates an `ABSENT` record for the workday. |
| Manager rejects an attendance excuse request | Request marked as `REJECTED` with reviewer note; attendance status remains `PRESENT_LATE` unexcused. |
| Database connection interruption | Server action catches error, logs structured diagnostic, and displays a user-friendly alert without data loss. |

## 5. Non-Functional Requirements
- **Security & Authorization:** Application-level role-based access control enforces that staff can access only their own records, managers can access their department records, and HR/Admin can manage company-wide records. Passwords hashed using bcrypt/argon2.
- **Data Integrity & Auditability:** All administrative edits, status overrides, and policy updates write an immutable entry to `AuditLog`.
- **Performance:** Dashboard views render via Server Components with cached queries; initial page load under 400ms on local ServBay environment.
- **Accessibility:** Semantic HTML elements, accessible form labels, high contrast status badges, and full keyboard navigation.
